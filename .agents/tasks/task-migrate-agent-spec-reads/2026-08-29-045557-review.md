# Harden the PATCH under-lock spec re-read (v2 review)

The v1 review returned NEEDS_CHANGES on a single blocking gap: the `api_agent_detail` PATCH branch re-read the matched agents-dir spec under the config lock with a bare `json.loads(f.read_text())` — the eighth sibling of the hand-rolled read the migration set out to close, and the one path where the migration's "every read hardened" invariant did not hold. The remediation commit (12aa07c28) replaces that bare re-read with an offloaded closure that applies the same `_read_agent_spec` gate as the migrated outer scan plus the stricter `_spec_path_is_safe` no-symlink/no-escape/no-sensitive fence (because this branch writes `data` back through `f.write_text`, a write-through copy-out), and degrades a refused/None/non-dict re-read to the handler's existing 409 `agent_changed` response instead of letting a swapped-in array/scalar reach `data["model"] = …` and raise a `TypeError` that escaped as an HTTP 500. Two revert-sensitive async regression tests were added.

Watch for: nothing blocking. The v1 blocker is closed at the code level, the closure's loop-variable binding is B023-clean, and the happy path is unchanged. The only residual is unrunnable tests — `pytest`/`aiohttp` are not importable in this network-restricted sandbox, so the two new async tests are verified by inspection and `py_compile`, not execution.

**Verdict**: APPROVED

## High-level view

The authoritative-re-read intent is preserved: the branch still fetches the post-lock copy of `f` (a concurrent PATCH may have superseded the pre-lock read), but now through `_reread_under_lock`, an `asyncio.to_thread`-offloaded closure. Offloading is required because the read runs while `_get_config_lock()` is held; awaiting the thread does not release the lock, so the read-modify-write stays atomic against sibling config writers.

The security posture of the re-read now matches the outer scan and the `migrate_agent_specs` copy-out site. `_read_agent_spec` supplies the size cap, sensitive-symlink refusal, UTF-8/AppleDouble screening and non-object rejection; `_spec_path_is_safe` adds the write-through fence (refuses any symlink, any resolved-parent escape, any sensitive path) because the branch's `f.write_text` would otherwise launder a swapped-in symlink's target back into the freely readable agents dir. Both guards run inside the offloaded closure before any mutation.

The fail-closed behavior is the load-bearing change. `_read_agent_spec` guarantees a dict on a non-None return, so a `None` from the closure is unambiguously "the file we matched pre-lock is no longer a spec we may safely read and rewrite," and the handler returns its own 409 concurrent-change response. The pre-remediation `TypeError`-to-500 path — a swapped-in array/scalar reaching `data["model"] = …` — is gone.

Completeness holds. A re-grep of `agents.py` surfaces no other agents-dir spec read on a bare `json.loads`: line 518 is the `_installed_agent_config()`/`defaults.json` GET read (the KiroCrew-owned fixed config, explicitly out of scope), line 1412 is a subprocess stdout decode, not a file read. The three `mcp.py` agents-dir scans and all seven original sites remain on the hardened reader.

### The re-read is now gated exactly like the write-through it feeds

The replaced code was a single `data = json.loads(f.read_text(encoding="utf-8"))` under `async with _get_config_lock()`, with no size cap, no symlink refusal, and no `isinstance(data, dict)` guard, followed later by `f.write_text(...)`. The remediation:

```python
_agents_dir = kiro_agents_dir_path()

def _reread_under_lock(
    spec_file: Path = f, agents_dir: Path = _agents_dir
) -> dict | None:
    if not _spec_path_is_safe(spec_file, agents_dir):
        return None
    return _read_agent_spec(spec_file)

data = await asyncio.to_thread(_reread_under_lock)
if data is None:
    return web.json_response(
        {"error": f"'{name}' changed on disk during update; retry.",
         "code": "agent_changed"},
        status=409,
    )
```

Two guards, in the right order for a read-then-copy-out site. `_spec_path_is_safe` runs first and rejects any symlink outright, any resolved parent that isn't the agents dir, and any sensitive path — the fence whose own docstring warns about the copy-out class, matching what `migrate_agent_specs` and `agent_spec_path`/`reset_agent_model` apply before a rewrite. Because `_read_agent_spec` alone only refuses a resolved-*sensitive* target, the `_spec_path_is_safe` layer is what closes the non-sensitive-target-outside-the-dir copy-out the reader would otherwise follow through `f.write_text`. `_read_agent_spec` then supplies the size cap, UTF-8 decode, and non-object rejection, returning `None` on any refusal and a guaranteed dict otherwise.

The `TypeError`-to-500 failure mode identified in v1 is eliminated at its root: a swapped-in top-level array or scalar is rejected by `_read_agent_spec`'s `isinstance(data, dict)` check and surfaces as `None`, so `data["model"] = …` is never reached on a non-dict. The 409 body reuses the `agent_changed` shape the branch already returns on other concurrent-change detections (lines ~1637, ~1653), so the fail-closed response is consistent across the branch rather than a new ad-hoc shape.

### Offload and closure binding are sound

Awaiting `asyncio.to_thread` does not release the config lock, so the read-modify-write stays atomic against sibling writers; the offload only moves the blocking disk work off the loop thread, matching the block's existing `KiroCrewConfig.load` / `run_in_executor` offloads.

The closure binds `spec_file=f` and `agents_dir=_agents_dir` as default arguments rather than closing over the loop variable `f`, the correct B023-clean pattern. `ruff check --select B023` reports two findings in this file, both pre-existing at the unrelated `_dn` lambda (lines ~1997–1998) and present identically on the base commit — the new closure adds none.

### Happy path unchanged

The existing `test_agent_detail_model_managed.py` cases (`test_patch_explicit_model_freezes` asserting 200 + `model == "claude-new"`, `test_patch_clear_model_resumes_tracking`, `test_patch_without_model_lifts_stale_bookkeeping_keys`) exercise the re-read → mutate → write flow and were not modified, so the mutate-and-write contract is still asserted. On a normal PATCH the re-read passes both guards (a real non-symlink file inside the agents dir) and returns the current dict, so the branch proceeds to the mutation and final `f.write_text` as before.

### The new tests exercise the hardened path and are revert-sensitive

`TestPatchUnderLockRereadIsHardened` reuses the `test_agent_detail_model_managed.py` harness (owner-boundary bypass, MagicMock PATCH request, `patch("kiro_crew.agent.KIRO_AGENTS_DIR", tmp_path)`) and simulates the concurrent swap by counting calls to a monkeypatched `agents_mod._read_agent_spec`: call #1 (the outer scan) returns the real spec so the file matches and the PATCH branch is entered; call #2 (the under-lock re-read, reached through the module-global name the closure resolves, so the monkeypatch applies) is the swap.

`test_refused_reread_returns_409_not_500` refuses call #2 (returns `None`, as the real reader would for an oversized/non-UTF-8/sensitive-symlink swap) and asserts the handler answers 409 and leaves the on-disk `model` at `claude-old` — proving the branch bailed before the write-through. `test_non_object_reread_returns_409_not_typeerror` overwrites the file with a top-level array `[1,2,3]` inside call #2 and then lets the *real* hardened reader reject it, so the 409 provably comes from `_read_agent_spec`'s non-object gate, not a hand-rolled `isinstance`.

Both would fail on a revert to bare `json.loads`: a bare re-read never calls the monkeypatched `_read_agent_spec`, so it would read the still-valid `kirocrew.json` on disk, proceed, and return 200 — failing the `== 409` assertions (and, in the refused case, the unwritten-disk assertion). The tests target the newly-hardened path specifically; a full aiohttp app fixture for the thin `api_mcp_active` wrapper was reasonably deferred since its `_collect_server_rows`/`_launch_specs_for` delegates already have direct skip-and-continue tests.

### Completeness re-confirmed

`_installed_agent_config()` (agents.py:518, `mcp.py:259/382`) reads the fixed KiroCrew-owned `~/.kiro/agents/kirocrew.json` / `defaults.json` config on the GET/config path — the class the task scope explicitly declared out of scope. It is not a glob-scanned read of arbitrary user specs and is not a missed sibling; leaving it a plain read is correct. Every remaining `json.loads` in `mcp.py` reads `_GLOBAL_MCP_JSON` or that config class, not the agents-dir spec glob. The migration's invariant — every read of the user-writable agents-directory spec glob goes through the hardened reader — now holds on all eight sites, including the previously-exempt under-lock re-read.
