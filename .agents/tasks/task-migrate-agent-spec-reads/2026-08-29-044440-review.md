# Migrate remaining agent-spec reads onto the hardened reader (v1 review)

Seven hand-rolled `json.loads(path.read_text())` reads of the user-writable, tool-shared `~/.kiro/agents/*.json` directory are moved onto the single documented hardened reader, so each inherits the size cap, sensitive-symlink refusal, AppleDouble/UTF-8 screening, and non-object rejection. The name→model job — which had grown three divergent spellings — is collapsed into one new `agent_discovery.agent_model_map()`, and `_build_kiro_model_map` and `SessionManager._resolve_agent_model` are routed through it. The remaining five reads (the `migrate_agent_specs` read/rewrite site, two `agents.py` scans, three `mcp.py` scans) call `_read_agent_spec` directly, and the rewrite site additionally keeps the stricter `_spec_path_is_safe` no-symlink fence in front of the read because it copies the parsed contents back out to disk. Failure semantics are preserved site-by-site: a refused/`None` spec degrades exactly like an absent one.

Watch for: an eighth read of the same directory — the under-lock re-read at `agents.py:1680` (`data = json.loads(f.read_text(...))` inside the PATCH branch, holding the config lock) — was intentionally left as a bare `json.loads` (confirmed). It re-reads the very file `f` the migrated outer scan already hardened, so a concurrent swap of that path to a symlink-to-sensitive or oversized file between the two reads bypasses every guard the migration just added; it also has no `isinstance(data, dict)` check and its `TypeError`/oversize failure modes escape the enclosing `except (JSONDecodeError, OSError)`. Also note the `api_mcp_active` and `api_agent_detail` scans have no direct regression test (likely).

**Verdict**: NEEDS_CHANGES

## High-level view

`agent_model_map` routes every read through `_read_agent_spec` and every model value through `spec_model`, removing the drift risk between the three former scans, and keys both the declared `name` and the file stem so callers that resolve by either spelling keep working. Both consumers keep their prior contract: `_build_kiro_model_map` its degrade-to-`{}` outer guard, `_resolve_agent_model` its `-> str`, dir-mtime+TTL cache, and `"auto"` default. One observable change rides along — the chat-persistence map now stores `"auto"` where it used to store a raw `""`/dict — which is the intended coercion, flagged only so it isn't read as accidental.

The `migrate_agent_specs` read/rewrite site is handled correctly: because it copies parsed contents back into the freely readable agents dir, it gates the whole read/rewrite on `_spec_path_is_safe` (rejects any symlink, escapes, sensitive paths) *before* the reader, closing the copy-out hazard the reader's resolved-target check alone would leave open.

The gap is completeness. The task's principle is that *every* read of the user-writable agents directory should be hardened, and the PATCH-path re-read at `agents.py:1680` — holding the config lock — still uses a bare `json.loads(f.read_text())` on the same `f` the migrated scan hardened. A concurrent swap of that path between the two reads defeats every guard the migration added, and its own `f.write_text` afterward is a write-through that would follow a swapped-in symlink. Leaving it means the migration's invariant does not hold on that path.

Test coverage for the migrated sync helpers is genuine and would catch a revert to bare `json.loads`. The two async handler scans (`api_mcp_active`, `api_agent_detail`) and the under-lock re-read are untested.

### `agent_model_map` as the single name→model reader

`agent_model_map(agents_dir=None)` walks `sorted(d.glob("*.json"))`, drops each file through `_read_agent_spec`, and on a non-`None` result keys `spec_model(data)` under both the truthy `name` and the file stem. `spec_model` folds a non-string `model` (the observed `{"id": ...}` and bare `null` foreign specs) to `"auto"` — the same rule the execution path (`normalize_agent_model`) applies, so the displayed model can't disagree with the one actually used.

The `break`-on-first-match of the old `_resolve_agent_model` inline loop is replaced by a dict lookup: behaviorally equivalent for resolution, and last-writer-wins on a name/stem collision instead of glob-order-wins.

The old `_build_kiro_model_map` stored the raw `data.get("model", "")` — `""` for a missing model, a raw dict for a structured one. It now stores `spec_model(...)`, i.e. `"auto"` for both. This is the intended correction and aligns the chat-persistence map with the session resolver, but it *is* an observable value change for any caller that distinguished `""` from a model id. The consumers hand the value to `.replace()`/comparison as a model string, so `"auto"` is the safe value.

### The `migrate_agent_specs` read/rewrite site and the copy-out fence

The loop runs `_spec_path_is_safe(spec_path, agents_dir)` first and `continue`s on failure, then reads via `_read_spec_capped` (a thin agent.py wrapper over `_read_agent_spec`), then rewrites via `_atomic_json_write` only when a bookkeeping key is present.

```
for spec_path in sorted(agents_dir.glob("*.json")):
    if not _spec_path_is_safe(spec_path, agents_dir):   # refuses ANY symlink,
        continue                                         # escapes, sensitive paths
    data = _read_spec_capped(spec_path)                  # size cap / utf8 / non-object
    if data is None:
        continue
    ...
    _atomic_json_write(spec_path, data)                  # os.replace -> swaps link, not through it
```

Why the stricter fence and not just the reader: `_read_agent_spec` resolves a symlink and reads its *target*, refusing only when that target is `is_sensitive_path`. A non-sensitive target outside the agents dir would still be read, and here the parsed contents get written back into the freely readable agents dir — laundering an arbitrary file's contents. `_spec_path_is_safe` closes that by rejecting `is_symlink()` outright, rejecting a resolved parent that isn't the agents dir, and rejecting sensitive paths. It is the complete fence for a read-then-copy-out site and matches what `agent_spec_path`/`reset_agent_model` already do. The `_atomic_json_write` `OSError` is caught and logged per-file, so the pre-existing skip-and-continue is preserved.

### The eighth read: unhardened re-read under the config lock

`api_agent_detail` (agents.py:1572) migrates its outer scan correctly — `_read_agent_spec(f)`, `None`-skip. But the PATCH branch, after matching, re-reads the same `f` under the config lock:

```
async with _get_config_lock():
    ...
    data = json.loads(f.read_text(encoding="utf-8"))   # line ~1680, bare, unhardened
    agent_name = spec_str(data, "name") or name
    ...
    f.write_text(json.dumps(data, indent=2) + "\n", encoding="utf-8")
```

The inline comment says this "stays a plain json.loads on purpose" and the orchestrator confirms it was left deliberately. It is a genuine gap against the task's stated principle. Between the hardened outer read and this re-read, a concurrent writer in the user-writable, tool-shared agents dir can swap `f` for a symlink whose resolved target is sensitive, or an oversized/non-UTF-8/non-object file. This re-read then:

- follows the symlink and slurps the target with no size cap (the reader's `safe_read_file_bytes` cap is gone here);
- has no `isinstance(data, dict)` guard, so a swapped-in top-level array/scalar reaches `spec_str(data, "name")` / `data.get(...)` / `data["model"] = ...`, and `data["model"] =` on a list/str raises `TypeError`;
- and that `TypeError` is not caught by the enclosing `except (json.JSONDecodeError, OSError)`, so it escapes as an HTTP 500 after the config-lock work has partly run.

The "re-read under the lock to get the authoritative copy a concurrent PATCH may have superseded" intent is legitimate and must stay; the authoritative re-read just needs to go through the same gate as the outer one — offloaded like the surrounding `asyncio.to_thread`/`run_in_executor` calls, since it runs under the lock. At minimum, re-apply `_spec_path_is_safe(f, kiro_agents_dir_path())` plus an `isinstance(data, dict)` check and turn a refused/non-dict result into the 404/409 the handler already returns. The `f.write_text` at the end of the branch is a write-through (not `os.replace`), so a symlinked `f` here would additionally write through to the target — the same copy-out class the `migrate_agent_specs` fence exists to prevent, unguarded on this path.

### Per-site failure-semantics preservation

Each of the seven enumerated sites degrades a refused spec exactly like an absent one, with no new raise on the happy path:

- `_namespaced_agent_file_exists` (agents.py:99): `None` → `continue`; a refused namespaced file no longer makes an app agent look present. The old `isinstance(data, dict)` is now guaranteed by the reader, so `data.get("name") == agent_name` is safe. Outer `except OSError -> return False` unchanged.
- `api_agent_detail` outer scan (agents.py:1572): `None` → `continue`, then match by `name`/stem. (The PATCH re-read is the separate gap above.)
- `api_mcp_active` non-kirocrew branch (mcp.py:783): `None` → `continue`; a match still returns the server list, a full miss still returns `[]`.
- `_collect_server_rows` / `_launch_specs_for` (mcp.py:2694, 2760): the old `except (OSError, JSONDecodeError)` + `isinstance(spec, dict)` guards fold into one `None` check; `spec.get(...)` is safe on the guaranteed dict.
- `_build_kiro_model_map` / `_resolve_agent_model`: outer `except` guards and defaults intact (above).

### Test coverage

The three new files plant *real* adversarial inputs against the *actual* migrated code paths, not mocks or static assertions, so they would fail if a site reverted to bare `json.loads`:

- `test_agent_model_map.py` writes an oversized file (under a monkeypatched `hooks.MAX_FILE_BYTES`), a `._real.json` AppleDouble, non-UTF-8 bytes, a top-level array and scalar, and a `evil.json -> protected.json` symlink with `is_sensitive_path` monkeypatched to flag the target, then asserts each is omitted from the map. It also asserts non-string/`null` models coerce to `"auto"` under both keys, and that `_build_kiro_model_map` returns `{}` both when every spec is refused (oversized) and when the scan raises.
- `test_migrate_agent_specs.py` asserts the happy-path rewrite still counts, that an oversized spec is left byte-for-byte unchanged (proving the read refused it *before* the rewrite), and — the copy-out test — that a `link.json -> outside.json` symlink leaves the target unchanged, stays a symlink, and is excluded from the count while a real sibling is still cleaned.
- `test_dashboard_agent_spec_reads.py` covers `_namespaced_agent_file_exists` (oversized → `False`, non-UTF-8 → `False`, sensitive-symlink → `False`, plus a control), and `_collect_server_rows`/`_launch_specs_for` (oversized + non-object skipped, clean sibling's server survives).

Not tested: the two async handlers `api_mcp_active` and `api_agent_detail` (both migrated, both would need an aiohttp request fixture); and the under-lock re-read at 1680, which has no coverage of the concurrent-swap failure mode. `pytest` could not be run in this environment (no `.venv`, `aiohttp`/`pytest` unimportable, PyPI blocked); `py_compile` passes on all changed files and the diff adds zero new `ruff check` errors versus `main`.
